# Accessibility gains and uneven inequality reductions from hospital expansion in China

This repository contains the analysis source code, processed analytical data, and reproduction workflows for the manuscript **“Accessibility gains and uneven inequality reductions from hospital expansion in China.”** The public workflow is designed to reproduce the reported Ga2SFCA-based accessibility results from released processed analytical outputs, recalculate the Shapley decomposition from the eight counterfactual scenario outputs, re-estimate the main SEE/CIE regression models, and regenerate the key main-text figures and summary statistics.

## Reproducing the results

Create the software environment from the repository root:

```bash
conda env create -f environment.yml
conda activate healthcare-accessibility
```

Check that the released reproduction inputs are present and have the required structure:

```bash
python reproduce.py --check-only
```

Run the public reproduction workflow:

```bash
python reproduce.py
```

The workflow can also be run in two sections:

```bash
python reproduce.py --section figures   # Figures 1–4 and Shapley decomposition
python reproduce.py --section see-cie   # SEE/CIE regressions and Figure 5
```

Generated files are written to `outputs/`. Temporary staged inputs and intermediate files are written to `.reproduction_work/`. Both locations are excluded from version control, while `outputs/README.md` remains tracked. To remove generated files:

```bash
python reproduce.py --clean-only
```

`outputs/generated_files.txt` lists the files generated by the most recent run.

## Public reproduction data

The released reproduction inputs are under `data/reproduction/`:

```text
data/reproduction/
├─ 2_2_multiscale_analysis/          # National/province/city/county summary statistics
├─ 3_2_ci_analysis/                  # GDP-ranked CI tables and compact Figure 4 inputs
├─ 4_2_shapley_decomposition/        # Eight counterfactual scenario summaries and reference Shapley output
├─ see_cie_regression_panel/         # Analysis-ready city-level SEE/CIE panel
└─ static/administrative_boundaries/ # Fixed 2023 province/city/county boundaries
```

The public workflow starts from these compact processed analytical products. It does not rerun national-scale OSM routing, construction of annual 1-km Ga2SFCA surfaces, GURS raster classification, grid-level socioeconomic matching, or longitudinal hospital/campus reconstruction. The corresponding upstream methods and implementation code are included in the repository, while the large externally sourced geospatial inputs are not bundled because of data volume and redistribution constraints.

### Hospital data

The complete record-level hospital and campus data, together with supporting provenance, are provided separately through the accompanying Figshare release. `data/example/hospital_records_2024_sample.csv` provides a small illustrative 2024 campus-level sample showing the structure of the hospital input used in the spatial analysis. The example file is not used by `reproduce.py`.

### Figure 4 inputs

The large grid-level CI-matched dataset is not required by the compact public workflow. Figure 4 uses released precomputed accessibility/GDP KDE curves and GDP-ranked concentration-curve points under `data/reproduction/3_2_ci_analysis/plot_inputs/`. Minority-share analyses reported in the Supplementary Information are outside the default main-figure reproduction workflow.

### Shapley decomposition

The repository includes outcome statistics for all eight combinations of road-network conditions, population distribution, and hospital supply (`A000`–`A111`). During reproduction, `code/recompute_shapley_from_scenarios.py` recalculates the exact three-component Shapley values from these eight scenario outputs, checks the efficiency property, compares the recalculated values with the released reference summary, and writes a newly generated `shapley_summary.csv` for plotting. The plotted Shapley results therefore do not use the released reference summary as their computational input.

## SEE/CIE analysis

The public SEE/CIE reproduction starts from the released city-level analytical panel:

```text
data/reproduction/see_cie_regression_panel/city_2014_2024_index.csv
```

This table contains the cumulative SEE/CIE measures, baseline and final accessibility and inequality outcomes, city-size classification, and model covariates required to re-estimate the principal regression models and regenerate Figure 5. Annual hospital/campus reconstruction and annual SEE/CIE construction are upstream stages and are not rerun by the compact public workflow.

The main regression outputs written to `outputs/regression/` include:

- `accessibility_models.txt`;
- `inequality_models_gini.txt`, `inequality_models_theil.txt`, and `inequality_models_atkinson_05.txt`;
- corresponding total-expansion model tables;
- `model_coefficients.csv`;
- `city_size_effects.csv`;
- `see_vs_cie_wald_accessibility.csv`.

Province fixed-effects and spatial-error analyses are retained as optional robustness scripts but are not run by the default public reproduction command.

## Administrative-unit matching in mapped figures

Province and county changes are matched across years using stable six-digit administrative codes. City-level statistics use the same normalized city analysis units (`city_name_norm`) as the upstream multiscale aggregation, including the study-specific treatment of municipalities and directly administered county-level units. Map joins are validated as one-to-one before spatial layers are exported, preventing duplicated-name administrative units from producing many-to-many matches.

## Optional reconstruction from raw inputs

`code/reconstruct_from_raw_inputs.py` provides an advanced workflow for reconstructing the analysis when the required raw population, OSM, hospital, and socioeconomic inputs are available. This upstream workflow is computationally intensive and is not required for reproducing the released principal results. The Rust routing source used by the travel-time stage is provided under `osm_batch_router_v2/`; compiled Rust artifacts are intentionally excluded.

Machine-dependent paths and compute settings are controlled through the `NC_*` environment variables defined in `code/config.py`. In particular, `NC_CPU_BUDGET` can be used to override the default CPU budget.

## Tests

Run the repository tests from the repository root:

```bash
python -m pytest -q
```

The tests include checks of the population-weighted inequality metrics and synthetic verification of the exact Shapley implementation.

## Software and reproducibility notes

All public reproduction paths are relative to the repository root. Machine-specific paths used by optional upstream reconstruction can be overridden with the `NC_*` environment variables defined in `code/config.py`.
